Renders specs/dashboard/design-dashboard.md, which is complete and locked at 202 requirements. No design decision is made in this file. Every value is transcribed from a numbered requirement and cited. Where this file and the spec disagree, the spec is right.

The six marks

R19 · R20 · R141

R20: marks are SVG geometry, never font glyphs or Unicode text, so they stay legible at 12px and survive desaturation. R19 defines the fill axis once, for every family:

● filled — a verdict exists ○ hollow — stopped before a verdict could be reached ◐ half — a verdict is pending (R22: the only rotating element in the product) ○ slashed — cancelled; resolves the greyscale collision with budget_exhausted (R142) ▲ fault — carries no fill meaning ✕ in square — integrity fault; carries no fill meaning ◌ connection unknown (R35b, R114) — a connection mark, not an outcome

Status families

R21 · R26 · R29 · R32

R32: a chip is mark + 12% hue tint + hue text + a text label. There is no filled-pill chip and no bare status dot anywhere in the product (two exceptions: the minimap R51, and the health strip R35a — both spatial indexes rather than labelled readouts).

R141/142b asserts per-family distinguishability, not global uniqueness. Desaturate and check each family separately: within a family, no two states may collapse.
Intentional cross-family identities — R142a, not defects

incomplete (run outcome) and rejected (adapter) both render neutral ●. cancelled (run outcome), retired (binding), and a queued delegation all render neutral ○. In each case the pair means the same thing under R31a, the states live in different tables with different labels, and reading one as the other produces no wrong conclusion. A test asserting global uniqueness would fail on a property the design deliberately wants.

Mandatory qualifiers

R25 · R32a

budget_exhausted and no_progress share a hue and a mark. They are separated by an inline qualifier naming the cause the runtime already records. The qualifier is not optional and is not a tooltip — a shared pair is always resolved in text.

Status chip vs flag chip

R50a · R50b

A flag chip is a separate achromatic class and never uses a status hue. R50b: the tool_result flag cancelled and the run outcome CANCELLED are the same word naming two different concepts. Achromatic lowercase monospace without a mark makes the flag unmistakable for the outcome chip.

R35a–R35d
